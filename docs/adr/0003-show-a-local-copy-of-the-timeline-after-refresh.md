# 刷新后 X 读到的是本地副本，新帖子放到 X 自己的「显示 N 推文」后面

「刷新后保留时间线」开启时，xnote 保存 X 收到的主页时间线数据（为你推荐、正在关注、置顶列表），保存在浏览器的 IndexedDB 里，12 小时内有效。页面刷新后 X 照常请求这条时间线（`requestContext: "launch"`），请求照常发出；xnote 只改变 X 读到的回答：X 读到副本，回答里的新帖子先留在内存里。X 之后会用副本的顶部游标请求更新的帖子，xnote 把留着的新帖子加进那个回答，X 就把它们放在自己的「显示 N 推文」后面。X 没有保存时间线的机制，它只在本地保存已看过的帖子 ID，所以只能这样做。这不违反 ADR-0001：xnote 没有自己发请求。

## Considered Options

- 不发出刷新后的请求，直接用副本作答：省一次请求，但刷新后的新帖子拿不到，只能等 X 下一次请求更新的帖子。
- 只保存帖子 ID，刷新后自己取帖子数据：要主动请求，违反 ADR-0001。
- 只恢复滚动位置：刷新后内容已经变了，没有意义。

## Consequences

- X 自己只在用户回到顶部时、或者第一次回答过时后才请求更新的帖子。副本显示后，xnote 调用一次 X 自己的轮询方法（`_foregroundPollAction`），请求由 X 发出，「显示 N 推文」随即出现。找不到这个方法时，要等 X 自己去请求。
- 用户点开「显示 N 推文」后，这些帖子才进入副本。没点开就刷新，它们不进副本，下次照样出现在「显示 N 推文」后面。
- 往下滚时 X 用副本里的底部游标请求下一页。服务器拒绝旧游标时，那一页加载失败。
- 依赖 X 的接口名称和回答结构。识别不出时，X 读到原来的回答，不影响 X 本身。
- 其他扩展也会改写同一个请求对象。xnote 读取的是浏览器原生的值，跳过它们的改写。
- 帖子内容保存在用户自己的浏览器里，不上传。
