# xnote 可以用本地副本回答 X 自己的时间线请求

「刷新后保留时间线」开启时，xnote 保存 X 收到的主页时间线数据（为你推荐、正在关注、置顶列表），保存在浏览器的 IndexedDB 里，12 小时内有效。页面刷新后 X 重新请求这条时间线（`requestContext: "launch"`）时，xnote 不让这次请求发出，而是用副本作答。X 没有保存时间线的机制，它只在本地保存已看过的帖子 ID，所以只能这样做。这不违反 ADR-0001：xnote 没有自己发请求，反而少发了一次。

## Considered Options

- 只保存帖子 ID，刷新后自己取帖子数据：要主动请求，违反 ADR-0001。
- 只恢复滚动位置：刷新后内容已经变了，没有意义。

## Consequences

- 新帖子靠 X 自己的机制出现：X 用副本里的顶部游标请求更新的帖子，并显示「显示 N 推文」。用户点开后，这些帖子才进入副本。
- 往下滚时 X 用副本里的底部游标请求下一页。服务器拒绝旧游标时，那一页加载失败，下次刷新会因为副本过期而恢复正常。
- 副本依赖 X 的接口名称和响应结构。识别不出时，请求照常发出，不影响 X 本身。
- 帖子内容保存在用户自己的浏览器里，不上传。
